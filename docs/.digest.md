# Documentation Digest

## STACK

- Python 3.12+, TypeScript 7, Node.js 20+, pytest 9, Vitest 4, FastAPI/FastMCP, Pydantic, SQLAlchemy, PostgreSQL, Alembic, Docker, OpenTelemetry.

## ARCHITECTURE

- Pattern: Hexagonal DDD across API, MCP, SDK, Core, PostgreSQL, and Alembic. Adapters depend inward; PostgreSQL owns persistence. Inject ports/services.
- SDK: Require agent and complete docs; preflight live targets; validate temporary-file graphs; preserve revisions/removals. Return `NO_CHANGES` only when ADR/feature text and publishable content/metadata match baseline. Dry runs skip preflight/publication. Provider CLI file-write permissions remain unresolved.
- Auth: `API_ADMIN_TOKEN` manages REST; `HARNESS_MEMORY_API_KEY` grants global `memory:read`; DB tokens use stored scopes. Reads span tenants unless scoped; `memory:publish` selects destination. Impact is MCP-only; identity/token/account reads require REST admin.
- REQUIRED: Scope reads by permission/tenant; bound snapshots; verify token digest/owner; use `/v1`; validate schema at startup. Enforce `ComponentScopePolicy`.
- REQUIRED: Publish complete REST snapshots; derive tenant from token; require admin body `tenant_id`; store normalized facts; reconstruct REST/SDK payloads; keep MCP reads independent of `snapshots.payload`.
- REQUIRED: List environment snapshot IDs; search current environments by default; history on request. Pin context; page newest first. Use project pointer only without environments. Bind cursors to scope/snapshot; enforce expected-current and idempotent publication.
- PROHIBITED: Framework/persistence imports in domain; unauthenticated tenant input; prompts executing business logic; runtime migration.

## TESTS

- Framework: pytest 9.x; Vitest 4.x.
- Commands: `./venv/bin/python -m pytest tests/unit`; `./venv/bin/python -m pytest tests/integration`; `./venv/bin/python -m pytest tests/e2e`; `npm --prefix sdk run test`.
- Coverage: Branch coverage; global `fail_under = 80` for `api`, `core`, and `harness_memory_mcp`. SDK has no coverage gate.
- Database: `harness-memory migrate`; status: `harness-memory migrate --status`.
- Test folders: `unit`, `integration`, `e2e` mirror source modules.
