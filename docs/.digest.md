# Documentation Digest

## STACK

- Python 3.12+, FastMCP 4.x, Pydantic 2.x, SQLAlchemy 2.x, PostgreSQL, Alembic, pytest 9.x.

## ARCHITECTURE

- Pattern: pragmatic DDD organized by business domain.
- Layers: `mcp/` adapters; `core/application/<domain>/`; `core/domain/<domain>/`; PostgreSQL infrastructure; Alembic migrations.
- DI: inject repositories and boundary services through constructors or application ports.
- REQUIRED: Keep dependencies inward; keep MCP tools thin; publish immutable versioned snapshots atomically; keep reads tenant-scoped and active-snapshot bounded.
- PROHIBITED: Import framework or persistence details into domain code; trust tenant identity from request payloads; create `queries/` or `session` infrastructure modules.

## TESTS

- Framework: pytest 9.x, pytest-asyncio, pytest-cov, FastMCP in-process client.
- Commands: `pytest tests/unit`, `pytest tests/integration`, `pytest tests/e2e`, `pytest --cov=core --cov=mcp`.
- Coverage: branch coverage; global `fail_under = 80` for `core` and `mcp`; no per-layer gate.
- Database commands: `harness-memory migrate`; read-only status: `harness-memory migrate --status`.
- Test folders: `unit`, `integration`, `e2e`; organize paths to mirror source modules.
