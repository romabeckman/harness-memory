# Documentation Digest

## STACK

- Python 3.12+, FastAPI, FastMCP 4.x, Pydantic 2.x, SQLAlchemy 2.x, PostgreSQL, Alembic, Docker, OpenTelemetry, pytest 9.x.

## ARCHITECTURE

- Pattern: hexagonal architecture with pragmatic DDD.
- Layers: `api/` and `harness_memory_mcp/` adapters; application ports/services; domain invariants; shared `core/infrastructure/postgres`; Alembic migrations.
- DI: inject ports and boundary services through constructors or explicit handler arguments.
- REQUIRED: Keep dependencies inward; keep graph reads tenant-scoped and snapshot-bounded; verify API-issued MCP tokens by active digest and owner; prefix REST routes with `/v1`; verify schema before production startup.
- REQUIRED: Keep MCP read-only; publish through REST with an active tenant-bound token carrying exactly `memory:publish`; derive tenant from its owner; protect management routes with `API_ADMIN_TOKEN`.
- PROHIBITED: Import framework/persistence details into domain code; trust unauthenticated tenant input; let prompts execute business logic; auto-migrate at runtime.

## TESTS

- Framework: pytest 9.x, pytest-asyncio, pytest-cov, FastMCP in-process client, PostgreSQL integration, HTTP/Docker E2E.
- Commands: `./venv/bin/python -m pytest tests/unit`, `./venv/bin/python -m pytest tests/integration`, `./venv/bin/python -m pytest tests/e2e`.
- Coverage: branch coverage; global `fail_under = 80` for `api`, `core`, and `harness_memory_mcp`.
- Database: `harness-memory migrate`; status: `harness-memory migrate --status`.
- Test folders: `unit`, `integration`, `e2e`; mirror source modules.
