# Documentation Digest

## STACK

- Python 3.12+, FastAPI, FastMCP 4.x, Pydantic 2.x, SQLAlchemy 2.x, PostgreSQL, Alembic, Docker, OpenTelemetry, pytest 9.x.

## ARCHITECTURE

- Pattern: hexagonal architecture with pragmatic DDD.
- Layers: `api/` and `harness_memory_mcp/` inbound adapters; application ports/services; domain invariants; shared `core/infrastructure/postgres`; Alembic migrations.
- DI: inject ports and boundary services through constructors or explicit handler arguments.
- REQUIRED: Keep dependencies inward; keep graph reads tenant-scoped and active-snapshot bounded; keep MCP tools thin and describe every tool argument in the generated schema; keep audits append-only and backpressure authentication denials under audit saturation; verify schema before production startup.
- REQUIRED: Verify API-issued MCP bearer tokens against active database digests; derive subject and tenant from token ownership.
- REQUIRED: Use stateless production Streamable HTTP. Keep malformed inputs as HTTP `200` JSON-RPC tool errors with `isError: true` and `INVALID_ARGUMENT`; map authentication to `401 invalid_token` and authorization to scoped `403 insufficient_scope`.
- REQUIRED: Prefix REST management routes with `/v1`; keep `/health`, `/docs`, and `/openapi.json` unversioned.
- REQUIRED: Alembic revision 006 seeds an `Admin` user and `Default Project`; revision 007 adds tenant-bound service accounts and non-expiring service-account tokens.
- PROHIBITED: Import framework or persistence details into domain code; trust tenant identity from payloads; let prompts execute business logic; auto-migrate at runtime.

## TESTS

- Framework: pytest 9.x, pytest-asyncio, pytest-cov, FastMCP in-process client, PostgreSQL integration, HTTP/Docker E2E.
- Commands: `./venv/bin/python -m pytest tests/unit`, `./venv/bin/python -m pytest tests/integration`, `./venv/bin/python -m pytest tests/e2e`.
- Coverage: branch coverage; global `fail_under = 80` for `api`, `core`, and `harness_memory_mcp`.
- Database commands: `harness-memory migrate`; read-only status: `harness-memory migrate --status`.
- CI: Ruff, PostgreSQL migration check, unit, integration, E2E, repository-root architecture validation, and coverage jobs.
- Test folders: `unit`, `integration`, `e2e`; organize paths to mirror source modules.
