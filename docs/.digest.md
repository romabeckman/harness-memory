## STACK

- Python 3.12+, TypeScript 7.x, Node.js 20+, Vitest 1.x, FastAPI, FastMCP 4.x, Pydantic 2.x, SQLAlchemy 2.x, PostgreSQL, Alembic, Docker, OpenTelemetry, pytest 9.x.

## ARCHITECTURE

- Pattern: hexagonal architecture across API, MCP, Core, and SDK.
- Layers: API/MCP adapters; SDK publisher; application ports; domain; PostgreSQL infrastructure; Alembic.
- SDK requires an agent via CLI, environment, config, or SDK options; model is independent.
- SDK compares local docs with the latest graph; bootstraps missing docs in bounded source batches; stores revision history.
- SDK: CLI progress/debug on stderr, JSON on stdout; debug adds redacted error stacks. Missing keys use paths; collisions hash; keyless entities without paths retry once.
- API reads are tenant-scoped except `API_ADMIN_TOKEN`. Admin publication uses body `tenant_id`. SDK defaults to `HARNESS_MEMORY_API_KEY`; CLI names: `harness-memory`, `hrns-memo`.
- DI: inject ports and boundary services through constructors or explicit handler arguments.
- REQUIRED: Keep dependencies inward; scope user/service-account reads to token owner; allow global admin reads; keep snapshot reads bounded; verify API-issued MCP tokens by active digest and owner; prefix REST routes with `/v1`; verify schema before production startup.
- REQUIRED: Keep MCP tools governed by `ComponentScopePolicy`; publish complete snapshots through REST. Derive ordinary token tenant from token owner. `API_ADMIN_TOKEN` has full REST privileges and cross-tenant data access; admin publication requires a destination `tenant_id` in the request body.
- PROHIBITED: Import framework/persistence details into domain code; trust unauthenticated tenant input; let prompts execute business logic; auto-migrate at runtime.

## TESTS

- Framework: pytest 9.x (backend), Vitest 1.x (SDK).
- Commands: `./venv/bin/python -m pytest tests/unit`, `./venv/bin/python -m pytest tests/integration`, `./venv/bin/python -m pytest tests/e2e`; `npm --prefix sdk run test`.
- Coverage: branch coverage; global `fail_under = 80` for `api`, `core`, and `harness_memory_mcp`.
- Database: `harness-memory migrate`; status: `harness-memory migrate --status`.
- Test folders: `unit`, `integration`, `e2e`; mirror source modules.
