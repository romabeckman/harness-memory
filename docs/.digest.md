# Project Digest

## STACK
- Python 3.12+, TypeScript 7.x SDK and 5.x Web, Node.js 20+, pytest 9.x, Vitest 4.x SDK and 1.6.x Web, Playwright, FastAPI, FastMCP, SQLAlchemy, PostgreSQL, Alembic, Next.js 15.

## ARCHITECTURE
- Pattern: Hexagonal architecture with pragmatic DDD across `api`, `harness_memory_mcp`, `core`, `sdk`, and `web`.
- Layers: Domain invariants; application use cases and ports; infrastructure adapters.
- DI: Constructor injection and explicit handler arguments.
- Web admin: server actions keep admin authority server-side, page credential review, resolve owners from bounded identity catalogs, and clear stale rows after failed refresh.
- Project environments: Projects page adds names; new projects receive production atomically.
- REQUIRED: Enforce globally unique tenant and project keys in fresh schemas; enforce stored token scopes; isolate Web admin credentials server-side; bound reads to active snapshots; publish complete snapshots through REST.
- REQUIRED: Keep SDK and Web on REST; keep persistence adapters and migrations responsible for PostgreSQL.
- PROHIBITED: Framework or persistence imports in domain; unauthenticated tenant authorization; runtime auto-migration; direct database or Python access from SDK or Web.
- REQUIRED: Require explicit organization selection for service-account creation; never infer the first active organization.
- REQUIRED: Keep aggregate Access Tokens & Credentials review free of issuance controls; owner pages own token issuance and secret reveal.

## TESTING
- Frameworks: pytest 9.x; Vitest 4.x for SDK and Web; Playwright for Web E2E.
- Python: `./venv/bin/python -m pytest tests/unit`; `./venv/bin/python -m pytest tests/integration`; `./venv/bin/python -m pytest tests/e2e`.
- SDK: `npm install`; `npm run lint`; `npm run build`; `npm run typecheck`; `npm run test` from `sdk/`, in that order.
- Web: `npm --prefix web run test`; `npm --prefix web run test:e2e`.
- Coverage: Python branch coverage gate is 80% across `api`, `core`, and `harness_memory_mcp`.
- Database: `harness-memory migrate`; inspect with `harness-memory migrate --status`. Fresh baseline: 001 tables, 002 indexes/foreign keys, 003 seed data; existing installations need a separate transition.
